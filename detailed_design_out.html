2. Detailed Design — Tamper Detection and Localisation (assigned module)

2.1 Component breakdown

ComponentResponsibility
SRMFilterFixed, non-trainable depthwise convolution applying 3 high-pass kernels (horizontal residual, vertical residual, Laplacian-style) to each input channel. 3-channel RGB in → 9-channel noise-residual tensor out. Implements the noise-residual half of FR-D1/FR-D2.
preprocess()FR-D1: deskew (row-variance search over ±10°), resize/normalise to 256×256 in [0,1], compute the ELA map (JPEG re-save at quality 90, pixel-wise difference). Returns the RGB tensor and the single-channel ELA map.
TamperLocaliser (model)The dual-stream encoder-decoder itself: two independent encoders (RGB+ELA, SRM residual), a fusion layer, and a decoder that outputs a per-pixel tamper logit map. Pure nn.Module, no I/O.
SyntheticTamperDatasetGenerates document-like images with a randomly spliced patch and a pixel-accurate mask, plus rotation/blur/noise/recompression augmentation (NFR-10). Stand-in for FSD (paper [29]) until real scans are available.
TamperLocalisationServiceThe module's only external surface (NFR-7): predict(image) runs preprocessing, the model, thresholding, connected-component region extraction and scoring, and returns the fixed output contract. Everything above is an implementation detail behind this one method.

2.2 Internal data flow

2.3 Algorithm detail

Deskew. For angle in [-10°, +10°] stepped by 1°, rotate the grayscale page and score it by the variance of row-wise pixel-intensity sums (text rows create high-variance peaks when horizontal; a skewed page blurs them together). Keep the angle with the highest variance. Cheap, needs no extra dependency, and good enough for the small scan tilts the problem calls for.

ELA. Re-save the page as JPEG at quality 90 and take the per-pixel absolute difference against the original, averaged over the 3 colour channels, normalised to [0, 1]. Untouched regions re-compress almost losslessly; edited regions (pasted from a different source, or re-saved at a different quality) show a brighter residual. Used only as one input channel alongside the RGB stream (Gap 4): the model is free to learn how much to trust it, rather than thresholding on it directly.

SRM kernels (applied per RGB channel, zero-padding, fixed weights, never updated by backprop):

horizontal residual   [[ 0,  0, 0], [0, -1, 1], [0,  0, 0]]
vertical residual     [[ 0,  0, 0], [0, -1, 0], [0,  1, 0]]
Laplacian residual    [[ 0,  1, 0], [1, -4, 1], [0,  1, 0]]

Loss. BCEWithLogits(logits, mask) + DiceLoss(logits, mask), where DiceLoss = 1 - (2|P∩T| + ε) / (|P| + |T| + ε) on sigmoid probabilities P against ground truth T. BCE alone is dominated by the large background class on a sparsely-tampered page; Dice pulls the gradient toward getting the (small) tampered region right, which is what IoU in the NFR-5 evaluation actually measures.

Region extraction. Threshold the heatmap at 0.5, label connected components with scipy.ndimage.label, rank components by pixel area, keep the top 5, and report each as {bbox: [x, y, w, h], confidence: mean heatmap value inside the component} — this is the "largest suspicious regions with coordinates" FR-D6 asks for.

Tamper sub-score. score = round(100 × (0.6 × peak_confidence + 0.4 × coverage_term)), where peak_confidence is the heatmap's maximum value and coverage_term = min(flagged_area_fraction / 0.2, 1.0). A small, high-confidence edit and a large, lower-confidence one can both reach a high score; a few stray low-confidence pixels cannot.

2.4 Reference implementation

The service method and its two private helpers, exactly as implemented in tamper_localisation/infer.py:

@torch.no_grad()
def predict(self, image: Image.Image, threshold: float = 0.5) -> dict:
    pre = preprocess(image, size=self.img_size)
    rgb = torch.from_numpy(pre["rgb"]).float().unsqueeze(0).to(self.device)
    ela = torch.from_numpy(pre["ela"]).float().unsqueeze(0).unsqueeze(0).to(self.device)

    heatmap = torch.sigmoid(self.model(rgb, ela))[0, 0].cpu().numpy()  # (H, W) in [0, 1]
    mask = (heatmap >= threshold).astype(np.uint8) * 255

    regions = self._top_regions(heatmap, threshold)
    score = self._tamper_score(heatmap, mask)
    return {"mask": mask, "heatmap": heatmap, "score": score, "regions": regions}

@staticmethod
def _tamper_score(heatmap: np.ndarray, mask: np.ndarray) -> int:
    """0-100: weighted blend of peak confidence and flagged-area coverage."""
    peak = float(heatmap.max())
    coverage = float((mask > 0).mean())
    coverage_term = min(coverage / 0.2, 1.0)
    return int(round(100 * (0.6 * peak + 0.4 * coverage_term)))

2.7 Complexity and performance (NFR-2)

Trainable parameters~1.1M (two encoders at 32/64/128 channels, 1x1 fusion, 3-stage transpose-conv decoder) — roughly two orders of magnitude below a ResNet-50 backbone.
Fixed parameters27 (the 3 SRM kernels x 3x3, never updated)
Forward pass costDominated by the two /8-downsampling encoders over a 256x256 input; comparable to running two small CNNs over a quarter-megapixel image, well within the single-consumer-GPU-or-CPU budget NFR-2 sets.
MemoryLargest activation is the SRM stream at full input resolution (9, 256, 256) before the first downsample; no activation ever exceeds a few tens of MB at batch size 1.

2.8 Error handling and edge cases

  • No tamper present. regions is an empty list and score is low; this is a normal, expected output, not an error.
  • Degenerate AUC. If a batch's ground truth is all-genuine or all-forged, roc_auc_score is undefined; evaluate.py reports nan for that batch rather than raising, so a batch imbalance does not crash an evaluation run (NFR-5).
  • Untrained / missing checkpoint. TamperLocalisationService runs with random weights if no checkpoint is given; callers must not treat that output as a real decision (see 2.6, Construction).
  • Device fallback. device defaults to CUDA if available, else CPU, satisfying NFR-2 without any caller-side branching.
  • Oversized/undersized pages. preprocess() resizes to a fixed 256×256 before the model ever sees the image, so input resolution cannot change the model's memory footprint or runtime.
  • Corrupt/unreadable image. Image decoding happens before predict() is called (at the API gateway); the service assumes a valid, already-decoded PIL.Image and is not responsible for file-format errors.

3. Detailed Design — Signature Verification Service

3.1 Component breakdown

ComponentResponsibility
SignatureDetectorObject detector that locates the signature region on the full page and returns a bounding box (paper [13]). FR-S1.
SignatureCleanerRemoves ruled lines, stamps and background noise from the detected crop before embedding. FR-S2.
SignatureEncoderWriter-independent Siamese/metric-learning encoder (papers [3], [6], [12]), frozen at inference; maps a signature crop to a fixed-length embedding vector.
SignatureServiceThe module's external surface: verify(page, signer_id) runs detect → clean → embed → compare and returns a similarity score and decision. FR-S3.

3.2 Data flow

3.3 Algorithm detail

Detection. A lightweight object detector (anchor-free, single class "signature") trained on signature bounding boxes over real document pages, following the multilingual detection approach of paper [13]; returns the highest-confidence box above a detection threshold, or "not found" if none clears it.

Cleaning. Binarise the crop, remove long straight lines (ruled lines under the signature) via morphological opening with a wide horizontal structuring element, and remove small disconnected blobs below an area threshold (stamp fragments, noise), following the cleaning stage of paper [13].

Comparison. similarity = max(cosine(embed(crop), ref_i)) for ref_i in references; decision = "genuine" if similarity >= threshold else "forged". The threshold is tuned on a validation split, not hard-coded, so it can be recalibrated per deployment (NFR-5).

3.4 Data structures

EmbeddingFixed-length float vector (encoder output dimension, e.g. 128), L2-normalised before cosine comparison
Reference setList of 1–5 embeddings per signer_id, loaded from the signatures table
Output{"similarity": float [0,1], "decision": "genuine"|"forged", "bbox": [x,y,w,h]}

3.5 Interface specification (NFR-6, NFR-7)

MethodSignatureService.verify(page: Image, signer_id: str) -> dict
ReplaceabilityAdding a signer is an INSERT into signatures, never a retrain (NFR-6); swapping the encoder for a better metric-learning model changes nothing outside this class (NFR-7).

3.6 Error handling

  • No signature detected. Returns decision = "not found" rather than guessing; the fusion stage treats this sub-score as unavailable (Section 6.4).
  • No reference signatures registered for the signer. Returns an error the orchestrator surfaces to the verifier (FR-U4 requires at least one reference before verification can run).

4. Detailed Design — OCR / Field Validation Service

4.1 Component breakdown

ComponentResponsibility
OCREngineText extraction; consensus across multiple engines for financial documents, following FORENSIQ's triple-OCR approach (paper [39]).
FieldValidatorPer-document-type regex/format rules on names, dates and ID numbers. FR-D3.
ArithmeticGateFor financial documents, checks that the total equals the net amount plus tax. FR-D4.
OCRServiceExternal surface: check(page, doc_type) -> dict, running extraction, field checks and (where applicable) the arithmetic gate.

4.2 Data flow

4.3 Algorithm detail

Extraction. For financial documents, run 3 independent OCR engines and take the field value a majority agree on (falling back to the highest-confidence single result if no majority), following FORENSIQ (paper [39]), which found this materially more reliable than any single engine. Non-financial documents use one engine.

Field validation. Each doc_type has a fixed set of regex/format rules (date formats, ID-number patterns, name character sets); a field fails if it does not match its rule, is empty where required, or (for a date) falls outside a sane range.

Arithmetic gate. abs(total - (net + tax)) <= tolerance (a small absolute/relative tolerance for rounding), applied only when doc_type is financial (invoice, receipt, bank statement).

OCR sub-score. 100 × (fraction of fields that passed) × (1 if arithmetic gate passes or is not applicable else 0.5) — an arithmetic failure is weighted as a strong signal without zeroing the whole sub-score outright, since a single mis-OCR'd digit can also fail the gate on an otherwise genuine document.

4.4 Data structures

Fieldsdict[str, str], keyed by field name (e.g. "date", "total", "id_number")
Flagsdict[str, bool], one entry per field, True = passed its rule
Output{"fields": dict, "flags": dict, "arithmetic_ok": bool|None, "ocr_sub_score": int}

4.5 Interface specification

MethodOCRService.check(page: Image, doc_type: str) -> dict (FR-D3, FR-D4)

4.6 Error handling

  • Unreadable text region. A field the OCR engine cannot read at all is recorded as failed, not silently omitted, so the sub-score reflects the gap.
  • doc_type with no registered rule set. Field validation is skipped and the OCR sub-score is derived from extraction confidence only; this is logged so new document types get rule coverage added, not silently scored as perfect.

5. Detailed Design — Fusion & Scoring Service

5.1 Component breakdown

ComponentResponsibility
ScoreFuserCombines the three sub-scores into one weighted authenticity score. FR-D5.
LabellerMaps the fused score to Genuine/Suspicious/Forged against configurable thresholds.
ReasonBuilderBuilds the plain-language explanation from the lowest-scoring sub-check. FR-D6.
FusionServiceExternal surface: score(signature, tamper, ocr) -> dict.

5.2 Data flow

5.3 Algorithm detail

final_score = w_sig * signature_sub_score
            + w_tmp * tamper_sub_score
            + w_ocr * ocr_sub_score          # w_sig + w_tmp + w_ocr = 1, default 1/3 each

label = "Genuine"     if final_score >= 80
      = "Suspicious"   if 40 <= final_score < 80
      = "Forged"       if final_score < 40

reason = template(lowest-scoring sub-check, its threshold, its evidence)
       # e.g. "signature similarity 0.41 (below 0.6 threshold)"

A weighted rule, not a learned end-to-end classifier (Gap 5/O5): each sub-score and the reason it produced stay inspectable, which a black-box classifier would not give (Gap 6/O6). Weights and thresholds are configuration, not code, so they can be recalibrated per deployment or document type without a redeploy.

5.4 Data structures

Weights{w_sig: float, w_tmp: float, w_ocr: float}, sum to 1, stored as configuration
Thresholds{genuine: 80, suspicious_floor: 40}, configuration
Output{"score": int, "label": str, "reason": str, "sub_scores": {signature, tamper, ocr}, "heatmap_key": str} — this is the row persisted into verifications (Section 7)

5.5 Interface specification

MethodFusionService.score(signature: dict, tamper: dict, ocr: dict) -> dict (FR-D5, FR-D6)

5.6 Error handling

  • A sub-score is missing (detector failed or timed out, Section 6.4). Its weight is redistributed proportionally across the remaining sub-scores, and the label is capped at Suspicious — a verification is never reported Genuine on partial evidence.
  • All three sub-scores missing. The request itself is reported as failed rather than fused into a meaningless label.

6. Detailed Design — Verification Orchestrator

6.1 Responsibilities

The orchestrator is the single entry point (FR-P1) for every verification: it pre-processes the upload, fans the three detector calls out, fans their results back in, calls fusion, writes the audit log, and returns to the caller. It contains no detection logic of its own.

6.2 Dispatch algorithm

def verify(document):
    pre = preprocess(document)                        # FR-D1, shared pre-pass
    tasks = {
        "signature": call_with_timeout(signature_service.verify, pre, timeout=6),
        "tamper":    call_with_timeout(tamper_service.predict,  pre, timeout=6),
        "ocr":       call_with_timeout(ocr_service.check,       pre, timeout=6),
    }
    results = await_all(tasks)          # fan-in; NFR-1 budget: 10s total per page
    for name, outcome in results.items():
        if outcome is TIMEOUT or outcome is ERROR:
            results[name] = None        # treated as missing evidence, not a crash

    fused = fusion_service.score(results["signature"], results["tamper"], results["ocr"])
    audit_log.write(document.id, fused)              # NFR-8, append-only
    if fused.label == "Suspicious":
        admin_queue.add(document.id)                  # FR-A2
    return fused

6.3 Full system sequence

6.4 Concurrency and failure handling

  • Each detector call runs under its own timeout (6s default, leaving headroom inside the 10s NFR-1 budget for pre-processing and fusion).
  • A timeout or exception in one detector does not cancel the others; the orchestrator awaits whichever complete and records None for the rest.
  • Fusion (5.6) is the single place that decides how to degrade a label when evidence is missing — the orchestrator itself makes no scoring decisions.
  • Audit log writes (Section 7) are the last step before returning, so a result is never handed to the client without a corresponding record.
