2.3 Algorithm detail

Deskew. For angle in [-10°, +10°] stepped by 1°, rotate the grayscale page and score it by the variance of row-wise pixel-intensity sums (text rows create high-variance peaks when horizontal; a skewed page blurs them together). Keep the angle with the highest variance. Cheap, needs no extra dependency, and good enough for the small scan tilts the problem calls for.

ELA. Re-save the page as JPEG at quality 90 and take the per-pixel absolute difference against the original, averaged over the 3 colour channels, normalised to [0, 1]. Untouched regions re-compress almost losslessly; edited regions (pasted from a different source, or re-saved at a different quality) show a brighter residual. Used only as one input channel alongside the RGB stream (Gap 4): the model is free to learn how much to trust it, rather than thresholding on it directly.

SRM kernels (applied per RGB channel, zero-padding, fixed weights, never updated by backprop):

horizontal residual   [[ 0,  0, 0], [0, -1, 1], [0,  0, 0]]
vertical residual     [[ 0,  0, 0], [0, -1, 0], [0,  1, 0]]
Laplacian residual    [[ 0,  1, 0], [1, -4, 1], [0,  1, 0]]

Loss. BCEWithLogits(logits, mask) + DiceLoss(logits, mask), where DiceLoss = 1 - (2|P∩T| + ε) / (|P| + |T| + ε) on sigmoid probabilities P against ground truth T. BCE alone is dominated by the large background class on a sparsely-tampered page; Dice pulls the gradient toward getting the (small) tampered region right, which is what IoU in the NFR-5 evaluation actually measures.

Region extraction. Threshold the heatmap at 0.5, label connected components with scipy.ndimage.label, rank components by pixel area, keep the top 5, and report each as {bbox: [x, y, w, h], confidence: mean heatmap value inside the component} — this is the "largest suspicious regions with coordinates" FR-D6 asks for.

Tamper sub-score. score = round(100 × (0.6 × peak_confidence + 0.4 × coverage_term)), where peak_confidence is the heatmap's maximum value and coverage_term = min(flagged_area_fraction / 0.2, 1.0). A small, high-confidence edit and a large, lower-confidence one can both reach a high score; a few stray low-confidence pixels cannot.

2.5 Error handling and edge cases

  • No tamper present. regions is an empty list and score is low; this is a normal, expected output, not an error.
  • Degenerate AUC. If a batch's ground truth is all-genuine or all-forged, roc_auc_score is undefined; evaluate.py reports nan for that batch rather than raising, so a batch imbalance does not crash an evaluation run (NFR-5).
  • Untrained / missing checkpoint. TamperLocalisationService runs with random weights if no checkpoint is given; callers must not treat that output as a real decision (see Section 2.4, Construction).
  • Device fallback. device defaults to CUDA if available, else CPU, satisfying NFR-2 without any caller-side branching.
  • Oversized/undersized pages. preprocess() resizes to a fixed 256×256 before the model ever sees the image, so input resolution cannot change the model's memory footprint or runtime.

3. Detailed Design — Remaining Services (design-level, not yet implemented)

3.1 Signature Verification Service (FR-S1–S3, O1, O2)

  • SignatureDetector.detect(page) -> bbox: object detector locating the signature region on the full page (paper [13]).
  • SignatureCleaner.clean(crop) -> crop: removes ruled lines, stamps and background noise from the detected crop (FR-S2).
  • SignatureEncoder.embed(crop) -> vector: writer-independent Siamese/metric-learning encoder (papers [3], [6], [12]); frozen at inference.
  • SignatureService.verify(page, signer_id) -> {similarity, decision, bbox}: runs the three steps above, then compares the embedding against the signer's 1–5 stored reference embeddings by cosine distance and thresholds the result. Adding a signer is an INSERT into signatures, never a retrain (NFR-6).

3.2 OCR / Field Validation Service (FR-D3, FR-D4)

  • OCREngine.extract(page) -> {field: text}: text extraction, consensus across engines for financial documents (paper [39]).
  • FieldValidator.check(fields, doc_type) -> {field: pass|fail}: per-document-type regex/format rules on names, dates and ID numbers (FR-D3).
  • ArithmeticGate.check(fields) -> bool: for financial documents, abs(total - (net + tax)) <= tolerance (FR-D4, paper [39]).

3.3 Fusion & Scoring Service (FR-D5, FR-D6, O5, O6)

final_score = w_sig * signature_sub_score
            + w_tmp * tamper_sub_score
            + w_ocr * ocr_sub_score          # weights configurable, sum to 1

label = "Genuine"    if final_score >= 80
      = "Suspicious"  if 40 <= final_score < 80
      = "Forged"      if final_score < 40

reason = template(lowest-scoring sub-check, its threshold, its evidence)
       # e.g. "signature similarity 0.41 (below 0.6 threshold)"

A weighted rule, not a learned end-to-end classifier (Gap 5/O5): each sub-score and the reason it produced stay inspectable, which a black-box classifier would not give (Gap 6/O6).

3.4 Verification Orchestrator (FR-P1)

def verify(document):
    pre = preprocess(document)                       # FR-D1
    tamper = tamper_service.predict(pre.image)        # parallel
    signature = signature_service.verify(pre.image, signer_id)
    ocr = ocr_service.check(pre.image, doc_type)
    # fan-in: wait for all three, with a per-service timeout (NFR-1)
    result = fusion_service.score(signature, tamper, ocr)
    audit_log.write(document.id, result)              # NFR-8, append-only
    return result

If one service times out or errors, the orchestrator does not fail the whole request: it records that sub-score as unavailable, lowers the confidence of the final label to at most Suspicious, and notes the missing check in the reason text — an unreachable detector degrades the decision rather than silently skipping a check.

5. System-Wide Error Handling

  • Invalid file / unsupported type. Rejected at the API gateway before reaching the orchestrator; never silently coerced into a wrong document type.
  • Detector timeout or failure. Handled by the orchestrator as in Section 3.4: the request still completes, with a capped confidence and an explicit note in the reason text, rather than a 500 error.
  • Auth / role failure. API gateway returns 401/403 before any detector runs (NFR-9); nothing is logged to audit_log as a verification attempt.
  • Concurrent admin decisions on the same document. feedback inserts are append-only; the latest row is treated as authoritative, and all prior ones remain in the table for audit (NFR-8).
